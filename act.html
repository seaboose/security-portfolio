01 / SURVIVE · CONTROLLED ARENA

Insight investigations

Verified examples · Windows preview · The optional Surge live collector is unsigned pending SignPath. Windows Application Control blocked live collection during testing. Both examples work with the supplied files.

I used Insight to trace two decisions back to the instructions and bytes that support them.

When does the cooldown expire?

Both builds return ready at exactly eight seconds. The equality case exposes the difference between greater than and greater than or equal.

Field guide

Use the supplied Windows desktop app. This exercise needs Python with Tk and the bundled example files. Leave Surge closed.

  1. Double-click Insight-Windows/Launch Insight.pyw. Choose File → Explore example · plain. In the routine selector choose main. Offsets in this exercise start at zero within each routine.
  2. Select the call at +0x5D. The byte view should highlight E8 00 00 00 00. The caller has just copied the same double into both input registers. Write down your prediction for equality.
  3. Select ready in the routine selector. Read the three instructions. Select +0x04 and check which condition sets the low return byte, AL. The comparison operands are deadline in XMM1 and current time in XMM0.
  4. Choose File → Explore example · encoded, then ready. Select +0x0E, +0x1A and +0x1C in turn. Track which constant survives when the inputs are equal.
  5. Final decision: At a deadline of 8 seconds, what does each build return at 7.75, 8.00 and 8.25? Write the three answers before opening the worked paper.

To check the experiment offline, open Investigation → Blind trials… → Verify and reveal both…. Expect two builds with an initial and revised attempt each. The scores belong to the recorded model attempts.

For an independent offline check of all four original model responses, open PowerShell in the Insight-Windows folder and run:

python -B -m insight.blind verify cases/survive-cooldown/blind --events cases/survive-cooldown/blind/events

Expect four scored submissions and the pair fingerprint b712d5b7d09bcd24fd2b51c4030d703dc46271f5c93253eea7b4ba792b8bd5c5. This command reads the saved evidence and works offline.

Worked paper

The caller in both builds passes equal values at main +0x57 and +0x5A (0F 28 CE, 0F 28 C6), then calls ready at +0x5D (E8 00 00 00 00). These are relocatable object bytes. The listing resolves the call to ready. At +0x62 the caller tests AL (84 C0); at +0x64 it jumps to failure if AL is zero (74 48).

The entire plain routine is eight bytes. At +0x00, 66 0F 2F C8 compares deadline against now. At +0x04, 0F 96 C0 sets AL when deadline is below or equal to now. At +0x07, C3 returns.

The encoded routine implements the same decision with two constants:

+00  66 0F 2F C8       compare deadline with now
+04  B8 C3 00 00 00    EAX = C3
+09  B9 5A 00 00 00    ECX = 5A
+0E  0F 47 C1          copy ECX to EAX if deadline is above now
+11  88 44 24 08       store AL on the stack
+15  0F B6 44 24 08    read that byte back
+1A  3C C3             compare AL with C3
+1C  0F 94 C0          set AL if equal
+1F  C3                return

Decision. At 7.75 both return 0. At 8.00 both return 1. At 8.25 both return 1. Equality leaves C3 in place in the encoded routine. This conclusion covers the finite inputs in the exercise.

Blind comparison on the published objects

The four fresh, local Qwen3 8B submissions all chose now <= deadline. The initial and revised answers for each build scored 3/9. All three equality tests passed and all six unequal cases failed. The strict comparison now > deadline scores 6/9, and the instruction-derived decision now >= deadline scores 9/9.

The paired rerun kept the historical anonymous packet IDs, disassembly and settings fixed. Each build received one initial request and one revision after public feedback. A fresh, stateless request received only its own packet and, for a revision, its initial answer and feedback. The two rebuilt objects have new file fingerprints and identical instruction bytes. The sealed report binds to these new files.

An earlier randomized run on these same files stopped after its first request for the plain build. The model marked its response as an abstention while supplying a predicate and a citation. The validator rejected it. That run has no score, revision or second submission. Its original event was retained in the private review records. No individual stage was retried.

What did Surge actually observe?

All nine sampled bytes matched the DLL. I followed the capture into Insight and carried the approved finding back into a Surge report.

Field guide

Use Windows x64 with Python 3.12 or later with Tk and the Microsoft Visual C++ x64 build tools. In the Surge folder, open a terminal and run py "Set up Surge.py" once. The setup downloads the pinned Windows runtime (about 151 MiB) and verifies its SHA-256. When it says Ready, close the terminal. Investigation and reporting work offline.

  1. Double-click Surge/Start Surge.cmd. Select Open evidence and pick observation.jsonl from this example. Expect six native records covering two ranges across the initial, sample and restored snapshots. In the Data preview, select row 1. Under Full record, find initial:LabCodeProbe and complete. The original machine-specific module paths have been shortened to the filename.
  2. Open Insight-Windows/Launch Insight.pyw. Choose File → Open Surge observation… → Choose observation… and select that same file. Choose Verify DLL…, select the supplied lab_module_v2.dll, then Open verified case. Read the file-byte and memory-byte lines. Expect 9/9 at RVA 0x1010.
  3. In Analyst notes choose New note while the cursor is at 0x1010. Write what the instructions do and name the sample limit. Use @0x1012 and @0x1015 to cite the two arithmetic instructions. Save the note. In the observation window choose Cite in saved draft.
  4. Choose Investigation → Review finding…. Check the cited bytes, enter your checks and limitations, choose Approve revision, then reopen Review finding… → Export… and save the file with a .json extension in a new folder. Close Insight.
  5. Back in Surge, choose Home → Try Demo → Survive → 3 Explain. Create an investigation with a title and author. Choose Preview Insight finding…, open your JSON, then Attach reviewed revision. Choose Cite E1 in observations in a new empty investigation. Enter your question and conclusion on their tabs. Enter a Revision reason, choose Save revision, then choose Continue to export → Export investigation report. Open the saved HTML offline.
  6. Final decision: Can the report substantiate the nine captured bytes, execution of this function with a particular argument, or the integrity of the entire DLL? Identify the claim supported by the capture. Compare your report with the worked paper.

If verification fails, reselect the supplied DLL and observation. A changed fingerprint is a useful rejection. An existing report may assign an evidence number other than E1.

Worked paper

Surge recorded the range LabCodeProbe at module-relative address 0x1010. Insight bound it to the selected DLL by SHA-256, 02c1d3df138b99ab71711d985d6ad11a78999a1a38f24774c8d01967563de329. The file supplied the instructions below. The capture independently supplied the same nine bytes with read mask 111111111.

RVA Exact bytes Interpretation
0x1010 8B C1 Copy the 32-bit input in ECX into EAX.
0x1012 83 F0 46 XOR EAX with 0x46.
0x1015 83 C0 11 Add 0x11 to EAX with 32-bit arithmetic.
0x1018 C3 Return to the caller.

From the instructions, an input of zero would produce 0x57. That is a prediction derived from the listing. The observation contains neither an input value nor a recorded return value.

Reporting decision. Cite the reviewed finding for this statement: “At the recorded sample time, the nine readable memory bytes at RVA 0x1010–0x1018 matched the corresponding bytes of the identified DLL.” Keep the arithmetic interpretation separately attributed to static analysis. Execution history and bytes outside this range remain unknown. In the exported HTML, follow the evidence citation and verify the finding revision, module fingerprint, and capture coverage.
